# Android 无障碍门禁

## 内容描述

- 可点击 Icon/Image 描述动作，例如“重新连接”，不是“刷新图标”。
- 纯装饰图形 `contentDescription = null`。
- 状态图标不能是唯一信息来源；同步提供文字或语义。

## 触控目标

所有交互目标至少 48×48dp。视觉图标可以较小，但点击区域必须满足要求。设备命令和发送/停止按钮尤其不能缩小。

## 对比度

- 普通文本与背景至少 4.5:1。
- 大文本和关键图标至少 3:1。
- 错误、审批、在线/离线不能只依赖红/绿颜色。

## 语义

- 页面和 section 标题使用 heading 语义。
- 消息、设备、工具等复杂行使用 `mergeDescendants`，避免 TalkBack 逐碎片朗读。
- Switch、选择、连接、审批使用标准 checked/selected/stateDescription。
- 进度提供可读百分比/步骤，而不是只显示转圈。

## 焦点与导航

- 焦点顺序遵循视觉阅读顺序。
- 弹窗出现后焦点进入弹窗，关闭后回到触发按钮。
- 键盘/DPAD 可操作所有主要流程。
- 导航切换后标题或首个主要元素获得合理焦点。

## 动态内容

- 新 SSE 消息不要强制抢走用户焦点；只在用户位于列表底部时自动滚动。
- 连接断开、命令失败、危险审批等关键状态通过可访问公告传达，但避免连续刷屏。
- 倒计时和频繁指标做节流，避免 TalkBack 重复朗读。

## 字体和屏幕

验证 200% 字体、窄屏、横屏、深色模式。文字不得覆盖按钮或被固定高度裁掉；必要时按钮文本换行或改用图标 + tooltip。

## 测试清单

1. TalkBack 完成连接配置、创建会话、发送消息和查看错误。
2. TalkBack 能区分用户消息、助手消息和运行状态。
3. 设备列表能朗读在线状态、能力和最后活动时间。
4. 高风险动作说明清楚且焦点不会逃出确认界面。
5. Compose semantics 测试覆盖主要按钮标签、选中状态和错误状态。
